# Учет веса животных

## Запуск

### Backend + PostgreSQL
```bash
cp .env.example .env
docker compose up -d --build
```
API: http://localhost:8000
Docs: http://localhost:8000/docs

### Frontend

```bash
cd frontend
cp .env.example .env   # VITE_API_URL=http://localhost:8000
npm install
npm run dev
```

UI: http://localhost:5173

### Первый вход

1. Зарегистрироваться на `/register`
2. Ссылку активации смотреть в логах backend: `docker compose logs backend`
3. Войти на `/login`
4. Admin: `UPDATE users SET role = 'ADMIN' WHERE login = 'admin';`

## Структура данных: 
Имеем следующую структура базы данных, состоит из 4 отдельных таблиц: 
- «animaltype»,
- «breed»,
- «animal»,
- «weighting».

«Animaltype» содержит данные о типе животного (корова, лошадь и т.п.) – наименование, идентификатор.
«Breed» содержит данные о породе животного – наименование, тип животного, идентификатор.
«Animal» содержит данные о животных – инвентарный номер, пол, кличка, дата прибытия, возраст прибытия (в месяцах), данные о породе животного, данные об одном родителе. Инвентарный номер уникальный.
«Weighting» содержит данные о взвешивании животного – животное, дата, вес в кг. При условии, что у одного экземпляра животного не может быть 2 взвешивания в 1 дату.

Дополнительные таблицы для хранения данных о пользователе. Произвольные поля, 2 типа пользователей – «user» и «admin»
 
## Задание:
1. Реализовать систему работы с указанной структурой данных.
2. Учесть добавление/редактирование/валидацию и удаление данных из каждой таблицы.  
Возможности админа:
- Работать с данными из всех таблиц
- Видеть всех пользователей
- Включать/отключать пользователей
- Возможности пользователя:
- Работать с данными из всех таблиц, но из таблицы «Weighting» видит только свои записи
3. Реализовать регистрацию пользователя для работы с системой(по паролю и логину, возвращает ссылку активации на почту) Логины пользователей уникальны. После регистрации пользователь создаётся в не активном состоянии. Становится активным переходя по ссылке полученной с регистрации
4. Обеспечить API для работы с системой
5. Обеспечить front-end для работы с системой (технологический стек для front-end на выбор собеседуемого, но оптимально – Vue/React).
